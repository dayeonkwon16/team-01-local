# 2단계 · 우리 팀 리뷰 분석 리포트 (4일차 오후 · 팀)

리포트 담당이 1단계를 한 PC에서 보냅니다. 대괄호 세 칸을 **우리 팀 말로** 바꿉니다(○○○ 자리). "진행할까요?"라고 물으면 내용이 맞을 때 `네, 이어서 해 주세요`.

```text
[1. 나의 기획 목적] ○○○(우리 팀 서비스)에 쓸, ○○○(장소) 손님이 좋아하고 불편해한 것을 찾는다
[2. 최우선 판단 기준(우선순위)] ○○○ (예: 건수가 많은 것보다, 우리 서비스가 풀 수 있는 것을 먼저)
[3. 타깃 대상 및 제외할 노이즈] 대상: ○○○ (예: 글이 있는 리뷰 전체) / 제외: ○○○ (예: 글자 몇 개뿐인 리뷰, 다른 업소 이야기, 광고 글)

위 세 칸을 기준으로 내 이름 폴더의 inputs/team_reviews.csv, inputs/team_reviews_source.md 와 맨 위 review-codebook.md 를 읽고 report/review-report.md 를 써 줘. 파일 값은 고치지 마.
1. 리뷰마다 기준표 태그를 붙여 report/tagged.csv 로 저장해. 열: 연번, 태그, 근거 문장(원문 그대로). 기준표 태그에 맞지 않는 리뷰는 '새 태그 후보'로 따로 모아 리포트에 표로.
2. /dataviz 로 태그별 리뷰 건수를 가로 막대 차트로 그려 report/chart.html 하나로 저장해. 제목은 결론 한 문장, 부제목에 분모·기간·출처(team_reviews_source.md의 장소·모은 날짜). 외부 주소(CDN) 없이.
3. 인사이트 3가지: 숫자(몇 건 중 몇 건) + 원문 한 줄(연번) + "그래서 우리 팀은" 한 줄
4. 맨 위 트랙 파일(emotion-keywords.md 또는 metrics.md)의 키워드·지표를 이 리뷰로 다시 세어, 오전 허심청 값과 나란히 표 하나로. 분모를 함께 적어.
5. 맨 위에 수집 기준 한 줄, 맨 아래에 '이 리뷰로 말할 수 없는 것'.
```

이렇게 되면 성공: `report/review-report.md`에 인사이트 세 개(숫자·원문 연번·"그래서 우리 팀은")와 트랙 표 하나가 있고, `report/chart.html`을 탐색기에서 더블클릭하면 막대가 보입니다. 결과는 팀 규칙대로 내 이름 폴더 안(예: `seoyun/report/`)에 생깁니다.

점검(2번 담당): 인사이트의 원문 한 줄을 `inputs/team_reviews.csv`에서 `Ctrl`+`F`로 찾습니다. 숫자의 '몇 건 중'이 1단계 건수와 맞는지 봅니다.

막히면:
- 막대가 안 보이면 → `chart.html을 열었더니 막대가 안 보여요. 원인을 찾아 고쳐 주세요.`
- /dataviz가 없다고 나오면 → 2번의 `/dataviz 로`를 지우고 보냅니다.
- 태그가 거의 '새 태그 후보'로 가면 → `새 태그 후보에서 많이 나온 것 세 개를 기준표 태그로 더해서 다시 세어 줘. review-codebook.md 는 고치지 말고 report/codebook-team.md 로 따로 저장해.`
- 원문을 못 찾으면 → `인사이트 ○번 원문을 team_reviews.csv 에서 글자 그대로 다시 옮겨 줘.`

다 되면: `/올리기` → 표에 `report/review-report.md`·`report/chart.html`이 있는지 보고 `좋아`. (`tagged.csv`와 `inputs/`는 팀 규칙으로 올라가지 않습니다)
